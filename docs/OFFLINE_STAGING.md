# Изолированные проверки без Docker

`sh tools/staging_offline_check.sh` запускает последовательный набор unit и
синтетических проверок на Python 3.11.2 и POSIX shell. Системные процессы,
production state и сеть им не нужны; тесты используют временные фикстуры и
не требуют KVM. Это воспроизводимый offline-контур, а не развёрнутый HUB и не
интеграционный staging. Изоляция платформы не изменяется. GitHub Actions
workflow запускает тот же набор на PR и feature-ветке и отдельно проверяет
Compose-модель с `.env.example`. Локальная проверка восстановления создаёт
временный SQLite WAL, архив и новый каталог назначения. Docker-сценарии
проверяют порядок действий через mocks. Результат удалённого CI неизвестен
до фактического выполнения.

Для полноценного staging необходим отдельно выделенный изолированный runtime
с фиксированными проверенными образами, собственными state, портами, именами,
locks и credentials, без доступа к системному Docker socket или production.
Нужны доступный сетевой namespace/loopback для тестов каналов и достаточная
память; ограничение в 3 vCPU и 3.8 GiB требует последовательного запуска.
В текущей среде Docker отсутствует, создание сокетов запрещено, `/tmp` noexec;
поэтому такой стенд здесь не запущен и виртуальная приёмка не заявляется.
