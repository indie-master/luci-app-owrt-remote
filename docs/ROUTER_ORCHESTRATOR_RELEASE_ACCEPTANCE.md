# Router Orchestrator — финальная матрица готовности

Status: IN DEVELOPMENT. **Экспериментальная ветка feature/indie-branding не готова к массовому развёртыванию**. Реальный Belt остаётся неизменным до поэтапной приемки.

## Завершено и проверено
- Точечное исправление экспорта OpenWrt vps_host без https:// применено на Belt, Xray PID/конфиг остались прежними.
- Работа шести роутеров (пять WSS и один legacy TCP) подтверждена оператором; Movietonn успешно подключен.
- Созданы изолированные прототипы мастера установки, Docker/Nginx/TLS-профилей, парных фрагментов WSS/REALITY, проверки pinned Xray-core и каталога резервных транспортов.
- Добавлена защитная блокировка Xray restart/reload для режима Docker HUB-only с отдельно обслуживаемым host-Xray (OWRT_REMOTE_XRAY_CONTROL_BACKEND=external_readonly).
- Добавлен read-only Docker migration gate: SQL integrity, сверка live Xray UUID/маршрутов, полная частная репетиционная копия HUB state и проверка SHA256 архива.
- Синтетические регрессионные тесты покрывают смешанный парк, архив истории, неинициализированные optional файлы, ошибочные и лишние UUID и отказ от небезопасного восстановления.
- Добавлен PRIVATE Docker shadow runtime: полное восстановление архивного state в отдельную директорию, SHA256-проверка файлов/исходника, доступ только к копии SQLite, no-network/no-published-ports/no-Docker-socket, UID владельца снимка и запуск настоящего HUB. GitHub Actions проверяет загрузку настоящего HUB на **синтетической** базе из шести роутеров с пятью историческими записями router_logs.
- В исходнике разработки отключена печать долговременного agent token в стандартный лог службы при запуске. Для старого исходника, включённого в репетиционный снимок, Docker shadow дополнительно использует --log-driver none.

## Критические задачи до финального релиза
| Компонент | Приёмка |
| --- | --- |
| Исходный v119 | Сохранить всё: UI, Auth, роли, LuCI, SSH, логи, WAN/DNS, WOL, статистика, backup/restore, web push/passkey, уведомления, self-update |
| Docker HUB | Рабочий проверенный образ с полным набором зависимостей и точным SHA source, persistent mount, HTTPS через внешний либо встроенный Nginx, отключение небезопасных host-only операций |
| Docker Xray | Авторизованный узкий lifecycle adapter без Docker socket у HUB; подготовка кандидата, config test, атомарное переключение и rollback |
| TLS и домен | Первичный GUI wizard, домен/DNS, HTTP-01/DNS-01 либо импорт certbot/PEM, тест сертификата, продление и reload |
| Транспорт | Профиль на каждый роутер; WSS и пилот REALITY/RAW; автоматическое формирование **обеих** сторон, проверка LuCI/SSH |
| Надёжный fallback | Локально подготовленный резерв, watchdog OpenWrt, hysteresis, cool-down, fail-closed, rollback без потери управления |
| Xray версии | Ветвление по архитектурам и версиям OpenWrt, digest pinned releases, compatibility matrix, staged A/B и откат |
| Новый роутер | Персональный одноразовый установочный токен, signed/pinned bootstrap, авто-регистрация серверных UUID без раскрытия общего hub_token |
| Интеграции | Опциональный Telegram bot и совместимые адаптеры Podkop/Forkop/Tachyon с разграничением прав |
| Docker-тесты | Реальная репетиция восстановления снимка Belt в изолированной среде, тест failure cases и временного отрыва соединений |
| Belt | Поэтапная миграция сначала HUB-only с host Xray/Nginx, затем отдельно Xray. Без потерь данных, истории и UUID, с точной проверкой каждого роутера |

## Порядок внедрения
1. Завершить реальный fresh install чистого VPS и роль Nginx/ACME.
2. В контейнере подтвердить исходные функции v119 и совместимость с OpenWrt.
3. Протестировать управление Xray, альтернативные транспорты, REALITY и откат на двухстороннем стенде.
4. Завершить одноразовую установку и автоматическое подключение нового роутера.
5. Сделать offline restore копии Belt и доказать сохранность всех файлов state, количества записей таблиц/истории, ключей и исходных профилей.
6. Выполнить только HUB cutover. Не запускать два пишущих экземпляра одновременно; не восстанавливать устаревшую SQLite поверх новых heartbeat.
7. После отдельной приёмки перенести Xray. TCP-сессии могут переподключиться, поэтому абсолютный zero-disconnect при stop/start обещать нельзя.
8. Контейнеризировать Nginx на Belt только если есть практический смысл; host-managed Nginx и сертификаты остаются поддерживаемым режимом.

## Обязательная неприкосновенность Belt
- Все действующие идентификаторы и reverse порты/маршруты: main, WR3000S_2, PaxoBs, Netis_N6_router5, Movietonn (WSS), AX3000T-Shteinberg (TCP).
- Полная папка /var/lib/owrt-remote: hub.db, auth, сессии, токены, история, журнал, уведомления, Push/VAPID, счётчики и другие существующие данные.
- /etc/xray/owrt-remote.json, Xray бинарник, systemd units, Nginx, конфигурация TLS и другие host ресурсы.
- Рабочие Podkop/Forkop/Tachyon настройки на роутерах и maintenance hold.

## STOP-факторы
Любой отсутствующий UUID, обратный порт, кусок истории, авторизация, несовместимая схема SQLite, ошибка source hash, неисправный ACME, разница Xray PID/JSON во время HUB-only миграции, невозможность отката или новая функция, сломавшая оригинальную — **релиз заблокирован**.

Дату принудительного перехода не назначаем: единственный критерий — полная функциональность и успешная приёмка.
